## 2. Gaps 🔴

1. **pro-tools page renders fabricated financials to real technicians.** Calls non-existent procedures through a cast (`legacyApi.technicians.myStats`, `legacyApi.pricingCoach.suggestions`) and falls back to hardcoded numbers (45 customers, 8500/7200 SAR revenue, expenses 3200, VAT 1275, loan 50000, franchise 12, participants 34, product "مانيكير سبا"). The file's own comment admits the procedures don't exist.
   - apps/web/src/app/(technician)/pro-tools/page.tsx:20-40 (cast), :68-115 (fallback numbers)
   - Severity: High (misleading business data in a shipped page). Fix: wire real routers (technicianEarnings exists — extend it) or gate the page behind a feature flag. Effort M.
2. **packages/ui escapes the i18n gate entirely.** 538 of 567 .tsx files contain hardcoded Arabic via `{ ar, en }` prop maps with `locale = 'ar'` default (e.g. AcademyCertificateBadge.tsx:26-43, 86-90; AccessibleSalonBadge.tsx:60-78, 184-185). The static-Arabic gate scans only apps/mobile/src and apps/web/src — never packages/ui. English-locale users see Arabic wherever callers omit the locale prop, and the ui package has no t() catalog integration.
   - scripts/find-static-arabic.mjs:24-27 (roots); packages/ui/src/components/AcademyCertificateBadge.tsx:12
   - Severity: High (convention violation at 538-file scale). Fix: extend the gate to packages/ui with its own allowlist, then migrate to locale-prop-or-t() sweep. Effort L.
3. **SEO is thin.** Only 33 of 321 pages export generateMetadata; sitemap.ts emits 32 URLs for ~321 routes; most pages are client components (364 'use client' files) so no per-page SSR titles. Group fallbacks exist (apps/web/src/app/(public)/layout.tsx:1-48 and root layout) so pages aren't untitled, but per-page metadata is missing for ~288 pages.
   - apps/web/src/app/sitemap.ts (32 urls); grep count generateMetadata=33
   - Severity: Medium. Fix: batch pageMeta() adoption on the public catalog pages first (lib/seo.ts helper already exists). Effort M.
4. **Single error boundary.** Only one error.tsx (app root); no group-level boundaries for (customer)/(public)/admin/tech, so a crash in a deep page unwinds to the root shell. Loading is better: 7 group-level loading.tsx ((customer), (public), admin, tech, (auth)/login, (auth)/register, root).
   - apps/web/src/app/error.tsx (only match); find apps/web/src/app -name error.tsx → 1
   - Severity: Low-Medium. Fix: add group-level error.tsx for (customer) and admin reusing ErrorAlert. Effort S.
5. **Dark-mode stragglers.** 7 light-only hardcoded colors: tech/gallery/page.tsx:140 text-red-600 and NpsCard.tsx:39,48 text-green-600 lack dark variants; the four beauty-shorts bg-white/10 entries are intentional (over video).
   - Severity: Low. Effort S.
6. **Doc drift in useVendorStore.** Comment claims "Store accounts are CUSTOMER-role users with a Vendor row (no VENDOR role)" — stale after the SELLER role + backfill shipped (R1).
   - apps/web/src/hooks/useVendorStore.ts:19-21. Severity: Low (code intentionally unchanged; comment only). Effort S.
7. **admin/payouts RequestsQueue locale bug.** Line 164 hardcodes `toLocaleDateString('ar-SA')` regardless of locale (the main table at line 93-95 does it correctly), and the reject button sends a hardcoded English `adminNote: 'Rejected'` at line 178.
   - apps/web/src/app/admin/payouts/page.tsx:164, 178. Severity: Low. Effort S.

## 5. Best-practice assessment

**React/Next patterns:** genuinely strong. Hydration discipline is near-perfect (every storage/window read is effect-guarded, theme is a pre-paint inline script with suppressHydrationWarning, auth hydration gates redirects in (vendor) layouts to avoid bounce races — (vendor)/(owner)/layout.tsx:20-40). The locale catalog and lazy Sentry chunk are Suspense-wrapped with documented root-cause fixes. Skeletons cover loading states at group level. The real cost is architectural: 364 client components across 321 pages means the app is a CSR-with-shell SPA in practice — SEO and first-paint suffer, and only 33 pages emit metadata.

**Accessibility:** good and enforced. axe gate with serious-violation thresholds and a documented moderate-allowlist policy (axe-a11y.spec.ts:70-84); dashboard tabs use role="tabpanel"/aria-labelledby (StoreDashboard.tsx:566-569); icon-only FAB carries aria-label (FloatingActionButton.tsx:26); 22 ui components use aria-label; e2e specs run responsive + tooltip a11y checks. Weak spot: packages/ui's bilingual cards (538 files) are outside the axe/static-Arabic gates entirely.

**SEO:** the weakest discipline. Group-level metadata fallbacks prevent untitled pages, and the pageMeta() helper (lib/seo.ts) is well-designed (locale-aware, canonical, OG/Twitter), but adoption is 10% of routes and the sitemap lists 32 of ~321 routes. hreflang is deliberately omitted (cookie-based locale, documented decision in lib/seo.ts:9-14) — defensible, but the metadata adoption gap is not.

**i18n discipline:** exemplary inside apps/web — typed TranslationKey union, lazy per-locale catalog import with prefetch, RTL/dir/lang sync, cookie persistence, and a CI gate (find-static-arabic.mjs --web) that currently passes with 0 findings. The 40-file allowlist (scripts/static-arabic-web-allowlist.txt) is mostly justified: 1-17 Arabic lines per file, dominated by demo person names (نورة/سارة/مها/ريم) in mock content. Two files could leave the allowlist cheaply: (public)/layout.tsx (17 lines of SEO metadata Arabic — could use the existing web-server t() like flash-deals does) and (auth)/login|register/loading.tsx (single hardcoded sentence each). The genuine violation is that packages/ui never enters the gate at all (538 files, {ar,en} prop maps defaulting to 'ar') — the gate convention is half-applied and should be extended.
