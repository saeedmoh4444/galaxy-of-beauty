## 2. Gaps 🔴

1. **Vendor portal has NO role guard** — severity: High. Unlike tech/admin, `vendor-portal/` has no `_layout.tsx`; any CUSTOMER (or logged-out user) can deep-link to /vendor-portal and the screens render (queries 401). Evidence: absence of `src/app/vendor-portal/_layout.tsx` (Glob); contrast `tech/_layout.tsx:19-29` and `admin/_layout.tsx:19-27`. Fix: add a vendor-portal `_layout.tsx` with `useAuthState` + `users.getMe` guard requiring role SELLER (or ADMIN), redirecting others to `/(tabs)/home`. Effort: S.
2. **Biometric login is cosmetic** — severity: High. `(auth)/login/index.tsx:39-44` `handleBiometricLogin` calls `authenticate()` then only shows a success toast — it never signs the user in (no token is stored, no credentials submitted). Fix: persist a credential/refresh token (SecureStore) after first password login and actually call `auth.login`/`auth.refresh` on biometric success. Effort: M.
3. **Detox e2e suites are unrunnable** — severity: High. `e2e/app.test.ts` (324 lines) and `e2e/tour.test.ts` (86 lines) import `detox`, but no package.json in the monorepo declares detox (verified: 0 matches in root/web/mobile package.json), there is no `.detoxrc.js`, and no `test:e2e` script. The only runnable test entry is `test:unit` (vitest) plus the Playwright web-export smoke. Fix: either add detox + config + CI job, or delete/migrate these specs to the Playwright `e2e-web` suite. Effort: M.
4. **Sentry release wiring is aspirational** — severity: Medium. `lib/sentry.ts:8` claims "releases wired by the EAS config plugin", but app.json:49 lists `@sentry/react-native` with no options, there is no `sentry.properties` (verified), and eas.json has no SENTRY_AUTH_TOKEN/ORG/PROJECT env. Also `sentry.ts:22-25` `beforeSend` does nothing while the comment claims "email-is-filtered" PII hygiene — no filtering implemented. Fix: add `"sentry-expo"` options (project/authToken via env) to the plugin and implement the email scrub in beforeSend, or delete the comment. Effort: S.
5. **`updates.fallbackToCacheTimeout: 0`** — severity: Low. app.json:64 — 0 means an update fetch failure instantly falls back to the embedded bundle (Expo recommends ≥2000ms); combined with `checkAutomatically: ON_LOAD` this makes OTA effectively build-only. Fix: set 3000-5000ms. Effort: S.
6. **Playwright e2e has no webServer and no CI wiring** — severity: Medium. `playwright.config.ts` (whole file, 21 lines) has no `webServer`; it requires a manually started `npx serve -s dist` on :8081 and API on :3000. Fix: add webServer entries (or document the bootstrap in CI). Effort: S.

## 3. Errors 🟡

1. **Dead code: `utils/deepLinks.ts`** — the entire `DEEP_LINK_CONFIG` (lines 6-82) and `resolveNotificationRoute` (85-102) are never imported anywhere (Grep across src returns only the definition file). Worse, the config's prefixes (`gob://`, line 7) contradict the app scheme `galaxyofbeauty` (app.json:7), and `resolveNotificationRoute` maps to non-existent root paths (`/bookings`, `/wallet`, `/notifications`, `/waitlist` — the real routes are `/(tabs)/bookings`, `/customer/wallet`, etc.). The live push-deep-link path is `utils/vendorOrders.ts:43` (`notificationRoute`), used by `hooks/useNotifications.ts:13,107-111`. Fix: delete deepLinks.ts. Effort: S.
2. **Hardcoded Arabic strings bypassing i18n** — `hooks/useBiometric.ts:57,66-68,78,81` (5 strings, e.g. promptMessage 'تسجيل الدخول بالبصمة') and `hooks/useCamera.ts:30-31` (camera permission Alert). All screens otherwise use `t()` keys (zero Arabic literals in src/app screens — verified by regex scan). Fix: move to `messages/mobile/customerB.ts` keys. Effort: S.
3. **Two stub screens ship "coming soon" Alerts** — `public/audio-rooms/index.tsx:78` (Join button → `Alert.alert(..., t('marketing.campaigns.coming-soon'))`) and `public/whatsapp-bot/index.tsx:63` (Connect → coming-soon). Both screens render full room/bot UIs that are non-functional. Effort to finish: M (audio room join) / S (remove or gate entry points).
4. **TODOs: user location never implemented in 3 screens** — `customer/home-service/index.tsx:18`, `customer/geofence-offers/index.tsx:20`, `public/salon-finder/index.tsx:23` all hardcode `DEFAULT_SAUDI_CITY` with `/* TODO: use user location */`, despite expo-location being installed and iOS/Android location permissions configured (app.json:22,31). Fix: one shared `useCurrentCity()` hook. Effort: S.
5. **Empty route dir `customer/vendor-portal/`** — exists with zero files (not a route, no references anywhere). Dead fragment; delete. Effort: S.
6. **Duplicate wallets** — `(tabs)/wallet/index.tsx` and `customer/wallet/index.tsx` are two independent implementations of the same feature (both query `wallet.getBalance`/`getTransactions`; the tabs one additionally shows loyalty + cashback). Not a bug, but drift risk. Effort: S (consolidate) / skip.
7. **Version drift: react 19.3.1 vs Expo's expected 19.3.0** — package.json:53-54 pins react/react-dom 19.3.1 while `expo/bundledNativeModules.json` expects `react: 19.3.0`. Patch-level, likely benign, but `expo install --check` will flag it. react-native 0.88.1 matches SDK 58 exactly (alignment is correct). Effort: S.
8. **Duplicate admin analytics** — both `admin/analytics/index.tsx` and `admin/analytics-v2/index.tsx` ship; unverified which is canonical (dead-code risk). Effort: S (confirm + retire one).
9. **Lint tolerates 200 warnings** — package.json:15 `eslint . --max-warnings 200`. Very high threshold; warnings accumulate invisibly. Effort: S.
10. **`console.warn` noise in offline queue** — `utils/offlineQueue.ts:105,138` (replay failure, unknown action type). Benign; consider captureError instead of console.
11. **push token registration timing** — `hooks/useNotifications.ts:86-120`: the effect re-runs on every `isAuthed` flip, re-requesting permissions and re-adding listeners; token registration happens only when authed (correct intent, minor churn). Also `scheduleReminder` is local-only (no server-side reminder). Low.
12. **ErrorBoundary renders raw `error.message`** — `components/ErrorBoundary.tsx:37-39` shows the technical message to users (i18n-adjacent issue). Low.

No `test.skip`, `it.todo`, `describe.skip`, or `.only(` anywhere in apps/mobile (verified). No `throw new Error` in app code (only the intentional `pipe` guard in `lib/trpc-react.tsx:129` and provider-context guards, which are correct). No "not implemented"/stub markers beyond items 3-4 above.

## 4. Missing ⚪ (parity vs web)

Every web feature area in the brief is present on mobile (seller role ✓, payout scheduling + admin payouts ✓, store dashboard ✓, wallet ✓, community ✓, reels ✓, subscriptions ✓, booking ✓). Verified absences:

- **Payout request creation**: mobile `earnings.tsx` shows history + schedule + invoice share, but has no "request payout now" action if web has one (web `(vendor)/vendor-portal/page.tsx` has no payout-related keys at all, so parity is effectively at/above web — note as observation, not a gap).
- **Vendor-portal role guard** (see Gaps #1) — the only true functional parity gap.
- Web `(vendor)/(owner)/store` owner screens: mobile has no store-settings/owner screens (product management on mobile is delete-only; `vendor-portal/index.tsx:21-23` comment says "browse-only by design — web-first dashboards"). Planned/acceptable.
- `resolveNotificationRoute` deep-link map (dead, see Errors #1) means non-order notification taps fall through to `/` — the live `vendorOrders.notificationRoute` covers order/booking types only.

## 5. Best-practice assessment

**expo-router**: Strong. Root Stack + (tabs) + per-area guarded layouts; all 60+ literal `router.push`/`replace` targets resolve to existing files (verified exhaustively, including `/customer/group-bookings/[id]`, `/public/blog/[slug]`, `/public/events/[id]`, `/public/tutorials/[id]`, `/marketplace/stores/[slug]`, `/technicians/[id]`); no dangling hrefs. The one hole is the missing vendor-portal guard (Gap #1) and the empty `customer/vendor-portal` dir. `app/_layout.tsx` registers `(auth)` screens individually (no `(auth)/_layout`) — works but is boilerplate-heavy.

**State**: Excellent for this codebase size. tRPC + TanStack Query with a 15-min access-token refresh link (`lib/trpc-react.tsx:61-132`) that retries a UNAUTHORIZED op exactly once behind a shared in-flight promise; global logout redirect only for pre-existing sessions (lines 151-167); auth state is a reactive token subscription (`hooks/useAuthState.ts`); socket token kept in sync (`setSocketToken` on login and on 401). Persisted catalog cache is whitelisted and buster-versioned. Only nit: two parallel wallet screens duplicate query wiring.

**i18n discipline**: Screens are fully on `t()` keys — a regex scan found zero hardcoded Arabic in any `src/app` screen. Violations are confined to hooks: `useBiometric.ts` (5 strings incl. OS-facing promptMessage) and `useCamera.ts` (1 Alert), plus English-only fallbacks like `ErrorBoundary` showing raw `error.message`. `LocaleProvider` + `locale === 'ar' ? 'ar-SA' : 'en-GB'` date/number formatting is applied consistently across vendor portal screens.

**Offline handling**: Genuinely implemented, not decorative: NetInfo → `onlineManager` + queued-action replay with dedup (`utils/offlineQueue.ts`), auto-sync on reconnect and at startup (`components/OfflineSyncProvider.tsx:24-48`), toast + bookings invalidation after sync, a dedicated offline screen whose retry actually probes connectivity and flushes the queue (`offline/index.tsx:16-25`), and 24h persisted catalog cache. Remaining rough edge: queued action failure handling is console.warn-only.

**Platform config**: Mostly solid — correct SDK-aligned versions (RN 0.88.1 ✓, react 19.3.1 vs expected 19.3.0 minor drift), camera/location permission strings in Arabic, WebRTC + expo-video + notifications plugins, OTA URL + projectId wired, EAS dev/preview/production profiles with per-profile API URL env. Weak spots: Sentry plugin has no authToken/project config so release tracking won't actually work (Gap #4), `fallbackToCacheTimeout: 0` undermines OTA (Gap #5), ios submit placeholders in eas.json:55-59 (`placeholder@email.com`, `ascAppId: "placeholder"`) are unreplaced, dev builds point `EXPO_PUBLIC_API_URL` at production (eas.json:18 — no staging env), and the bundled assets are tiny (284KB total, no asset-budget concern).
