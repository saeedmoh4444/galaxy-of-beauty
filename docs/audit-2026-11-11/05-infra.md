## 2. Gaps 🔴

1. **CRITICAL — all API realtime emits are silent no-ops in production.** `initializeSocket` is only ever called in `socket/server.ts:33` (and tests). The tRPC routers run in the Next web process where module-level `io` is null, so `emitToUser/emitToTechnician/emitToAdmin` no-op (socket/index.ts:370-395). Every call site (bookings.ts:499-501,966-975, chat.ts:60, notifications.ts:173, payments.ts:326-334,548-556, video.ts:37, vendorPortal.ts:1432-1433) emits nothing. Only client↔client video signaling works. Tests pass because socket.test.ts boots the server in-process. Fix: server-side Socket.IO client + Redis adapter in the web process (or move emits behind Redis pub/sub into the socket process). Effort M.
2. **Non-idempotent cashback on retry** — handleWalletJob increments bonusBalance then inserts walletTransaction with unique idempotencyKey (handlers.ts:82-105; schema unique at packages/db/prisma/schema.prisma:428 area). A retry after commit double-pays and marks the job failed. Fix: idempotencyKey lookup first / upsert. Effort S.
3. **reconciliationWorker omitted from graceful shutdown** (workers/index.ts:229-245) and from startWorkers log (255-271); `getAllQueues()` omits gob-ops + gob-webhooks (queues/index.ts:229-245); QUEUE_REGISTRY omits gob-ops/gob-webhooks/gob-media/gob-reconciliation so the D2 health monitor and `gob_queue_depth` metric blind to 4 queues (queueHealth.ts:23-36). Effort S.
4. **Reconciliation mismatches never alert** — handlers.ts:1291-1298 logs console.error and returns; the comment "alerting can pick them up" is false (nothing consumes logs; sendAlert is only called for disk/queue-health/breaker, handlers.ts:1139,1150, circuitBreaker.ts:121). Fix: sendAlert + captureMessage on mismatch. Effort S.
5. **Orphan socket events**: `waitlist_update` client listener has no server producer (emitToWaitlist unused outside tests); `new_message`, `video_call_started`, `booking_updated` fallback have no client listener. Effort S-M.
6. **CI docker gate builds dev images only** — ci.yml:480 `docker compose build` resolves web/socket `target: development` from docker-compose.yml:56,89; the production/runtime/worker stages are never built in CI. Fix: `docker compose -f docker-compose.yml -f docker-compose.prod.yml build`. Effort S.
7. **Staging has no nginx/TLS despite docs** — docs/DEPLOYMENT.md:261 says "nginx on :8080"; docker-compose.staging.yml defines only postgres/web/socket/worker (its own header admits nginx "deliberately not redefined"). Effort S.
8. **Mobile Sentry DSN not wired anywhere** — eas.json:17-47 env blocks set only EXPO_PUBLIC_API_URL; EXPO_PUBLIC_SENTRY_DSN must be hand-set in EAS env vars. initSentry is DSN-gated no-op otherwise (apps/mobile/src/lib/sentry.ts:15). Effort S.
9. **autoRenew is dead** — renewDueSubscriptions always EXPIRES every due ACTIVE sub regardless of autoRenew (`renewed` const is 0, subscriptionRenewal.ts:28-41); no charge path exists, so promised auto-renewal silently converts to expiry. Effort M (needs gateway capture).
10. **Socket URL fallback trap** — client falls back to `hostname:4001` (web useSocket.ts:18-20, mobile useSocket.ts:16); in prod compose port 4001 is unpublished and nginx only proxies /socket.io/ (nginx-compose.conf:37-51). If NEXT_PUBLIC_SOCKET_URL build arg is empty (docker-compose.prod.yml:51 defaults `:-`), connections fail. Effort S.
11. **No path filters on ci.yml** — all 11 jobs run for any file change; only mobile-eas-build filters. Effort S.
12. **Alertmanager webhook is a placeholder** — `https://example.com/alerts` with TODO(ops) (deploy/alertmanager.yml:21); alerting.ts degrades to a log when ALERT_WEBHOOK_URL unset (alerting.ts:47-51). #562 alerting therefore not paging anywhere as committed. Effort S.

## 5. Best-practice assessment (honest)

**CI rigor: high.** 11 gates incl. axe (chromium), size budgets, coverage ratchet actually wired (vitest.config thresholds + `--coverage`), k6 gate with real budget, contract gates (router inventory sha256, openapi generatable), dependency-audit baseline ratchet, concurrency control, artifact uploads, EAS verify-gate with hermesc export. This is unusually thorough. **Secrets handling: good with caveats.** Prod compose forces secrets via `:?required` interpolation and resets dev defaults; env files gitignored; EXPO_TOKEN presence-gating pattern is clean. Caveats: no `permissions:` blocks on ci.yml/deploy/mobile-eas (default token scope), docker job untagged, deploy relies on GH environments config that can't be verified in-repo. **Observability: strong scaffolding, unproven last mile.** prom-client /api/metrics + queue gauges + breaker gauges, exporters, Grafana dashboard, alerts.yml rules, Sentry (web bundle B1 gate, mobile DSN-gated, server DSN-gated), alerting.ts with dedupe, queue-health monitor — all real. But the biggest observability blind spot is behavioral: the entire realtime notification layer is dead in production (Gaps #1) and no test or alert would notice; the alertmanager receiver is a placeholder, so #562 paging is theoretical as committed.
