# Deep Audit — 2026-10-30 (post reels Phases 1–3)

> Honest gap analysis after the reels program closed (#541–#558, master `4e6b5231`).
> Companion to the root `brain_code.md` (architecture) and `Rules_to_make_well_archtichtrue-platform.md` (rulebook).
> Verdict: **the codebase is in excellent shape; the risk now lives in infrastructure and operations, not in code.**

## 1. What is solid (do not re-litigate)

- **Type safety end-to-end** — tRPC + Zod + TS 6 strict, 267 routers / 1,211 procedures, every router barreled, contract-gated (counts + tier map + hash).
- **Money integrity** — fail-closed gateways, verified callbacks, idempotency keys, `$transaction` everywhere money moves; regression-pinned by `money-integrity.test.ts`.
- **Analytics architecture** — materialized read-models (VendorDailyStat, ReelDailyStat) in NOON-UTC buckets; the portal never aggregates live order tables. The reels Q3 attribution (7-day tap→order window) proves the pattern generalizes.
- **i18n** — zero static Arabic; per-platform + per-locale catalogs; drift/leak/locale-split gates; bundle classes ratcheted at 221/213/298/226 KB gz.
- **CI as a real gate** — 9 checks including E2E on three browsers, axe a11y, size budgets, cycle checks.
- **Test culture** — 246 api test files + E2E + k6 scripts; TDD is the working norm.

## 3. What we deliberately do NOT adopt (and when to revisit)

- **Kubernetes** — Docker Compose + PM2 covers 1–10 servers. Revisit at 100K+ users or when the team exceeds ~5 engineers.
- **Kafka** — BullMQ on Redis is plenty. Revisit only for massive event streaming or cross-service fan-out.
- **Microservices extraction** — the domain barrels are the seams; extract ONLY when a domain needs independent scaling (media transcoding is the first candidate).
- **Elasticsearch** — Postgres ILIKE + JSONB handles Arabic search today. Revisit when search relevance becomes a product feature.
- **Feature-flag SaaS** — a `FeatureFlag` table + middleware exists; adopt runtime delivery tooling (LaunchDarkly-class) only when staged rollouts of risky features become routine.

## 4. Known operational risks (accepted, monitored)

- **E2E login flake** — bcrypt-under-load timeouts under parallel browser workers; retries absorb most. Rule: read the playwright-report artifact before ever blaming a diff.
- **CI trigger gaps** — pushes occasionally create no workflow run; recovery = merge-master push (a real merge commit always triggers).
- **Single DB/Redis** — accepted at this scale; backups + alerting (items 2, 8) are the mitigation until replication lands.
- **Background watchers reaped under memory pressure** — one-shot checks on demand.
